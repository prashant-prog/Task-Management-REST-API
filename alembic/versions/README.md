# Alembic Migration Versions

This directory contains the immutable, version-controlled database migration scripts generated by **Alembic**.

Each file represents a discrete schema revision with explicit forward (`upgrade()`) and backward (`downgrade()`) migration functions.

---

## 1. How Alembic Tracks Revisions

Alembic uses a directed acyclic graph (DAG) where each revision script references its parent revision (`down_revision`):

```
Base Database State (empty)
        │
        ▼
Revision: 6d2e2d54fc42  (Revises: None)
"create users and tasks tables"
        │
        ▼  (Future revisions chain downward)
```

In the PostgreSQL database (`task_db`), Alembic maintains a single-row metadata table named **`alembic_version`**:
```sql
SELECT * FROM alembic_version;
```
```text
 version_num  
--------------
 6d2e2d54fc42
(1 row)
```
When `alembic upgrade head` is invoked, Alembic checks the database's `version_num`, identifies all unapplied revisions in this folder, and executes their `upgrade()` functions inside a transaction block.

## 3. Anatomy of a Migration File

Every migration file follows a standard contract:

```python
# Unique identifier and link to previous revision
revision: str = "6d2e2d54fc42"
down_revision: str | None = None
branch_labels = None
depends_on = None


def upgrade() -> None:
  """Apply schema changes to move the database forward."""
  op.create_table(...)
  op.create_index(...)


def downgrade() -> None:
  """Reverse schema changes to roll the database back."""
  op.drop_table(...)
  op.drop_index(...)
```

## 4. How to Generate a New Migration

When you add or modify models in `app/models/`:

```bash
# 1. Generate revision script
alembic revision --autogenerate -m "add tags to tasks table"

# 2. Inspect the newly created script in this directory

# 3. Apply the migration
alembic upgrade head
```
