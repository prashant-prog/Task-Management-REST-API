# Database Models (`app/models/`)

This directory contains the **SQLAlchemy 2.0 ORM models** representing the persistent relational schema in PostgreSQL.

## 3. Models Breakdown

### 1. [`user.py`](user.py) — `User` Model
Represents user accounts in the system.

- **Attributes:**
  - `id`: Auto-incrementing primary key.
  - `email`: Indexed, unique string for login identification.
  - `hashed_password`: Argon2 password hash.
  - `is_active`: Boolean status flag (allows deactivating accounts without deleting records).
  - `created_at` & `updated_at`: Timezone-aware UTC timestamps automatically generated by PostgreSQL (`func.now()`).
- **Relationship:**
  - `tasks`: 1-to-many relationship with `Task`. Configured with `cascade="all, delete-orphan"` so deleting a user removes all their tasks from memory.

---

### 2. [`task.py`](task.py) — `Task` Model & Enums
Represents to-do items owned by users.

- **Enums (`enum.StrEnum`):**
  - `TaskStatus`: `PENDING ("pending")`, `IN_PROGRESS ("in_progress")`, `COMPLETED ("completed")`.
  - `TaskPriority`: `LOW ("low")`, `MEDIUM ("medium")`, `HIGH ("high")`.
  - Configured with `native_enum=False`: stored as `VARCHAR` with a SQL `CHECK` constraint. This avoids PostgreSQL schema locks and simplifies future enum additions.
- **Attributes:**
  - `id`: Primary key.
  - `title`: Short task description (indexed).
  - `description`: Optional long-form markdown/text.
  - `status` & `priority`: Indexed string enums.
  - `due_date`: Optional timezone-aware UTC deadline (indexed for fast deadline sorting).
  - `user_id`: Foreign key referencing `users.id` with `ondelete="CASCADE"`.
- **Relationship:**
  - `owner`: Many-to-one relationship back to `User`.

## 4. Modern SQLAlchemy 2.0 Syntax Highlights

- **`Mapped[T]` and `mapped_column()`:** Replaces legacy `Column()` syntax with strict type annotations recognized by static type checkers (`mypy`, `pyright`, IDEs).
- **Composite Indexes:** Key filtering/sorting fields (`user_id`, `status`, `priority`, `due_date`, `created_at`) are indexed so database scans run in `O(log N)` instead of `O(N)`.
